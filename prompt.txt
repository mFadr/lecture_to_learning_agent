# MASTER PROMPT: Vývoj lokálního AI agenta Lecture-to-Learning pro Windows

## 1. Role a hlavní cíl

Jsi seniorní Python developer, AI engineer, softwarový architekt a UX designer. Tvým úkolem je navrhnout a implementovat kompletní funkční desktopovou aplikaci s názvem **Lecture-to-Learning Agent**.

Aplikace slouží vysokoškolským studentům k převodu přednáškových materiálů ve formátu PDF na kvalitní, strukturované a vizuálně přehledné studijní podklady.

Nejde pouze o chatbot, který shrnuje text. Jde o lokálního AI agenta, který dokáže:

1. Načíst jeden nebo více PDF souborů.
2. Extrahovat text, strukturu dokumentu a informace z jednotlivých stránek.
3. Rozpoznat hlavní témata, podtémata, definice, vzorce, příklady a vztahy mezi pojmy.
4. Vytvořit přehledné studijní materiály odpovídající skutečnému obsahu přednášek.
5. Identifikovat konkrétní tematické příklady uvedené v PDF a převést je do vizuálních reprezentací.
6. Vytvořit otázky, flashcards, procvičovací testy a další pomůcky pro aktivní učení.
7. U každého důležitého výstupu uvádět dohledatelný zdroj v původním PDF.
8. Umožnit uživateli interaktivně procházet, upravovat, exportovat a znovu generovat výstupy.

Výsledkem má být reálně spustitelná aplikace pro Windows, nikoliv pouze prototyp, návrh architektury nebo ukázka kódu.

---

## 2. Základní technické požadavky

Navrhni aplikaci podle těchto priorit:

- Lokální provoz na Windows 10 a Windows 11.
- Primárně Python.
- Uživatelské rozhraní desktopové aplikace.
- PDF jako hlavní vstupní formát.
- Možnost používat lokální jazykové modely bez internetu.
- Volitelné připojení ke cloudovým LLM přes API.
- Oddělení logiky agenta od poskytovatele LLM.
- Bezpečné zacházení s lokálními soubory a API klíči.
- Modularita, aby bylo možné přidávat další funkce.
- Nízké nároky na instalaci a srozumitelné ovládání pro běžného studenta.

### Doporučený technologický stack

Použij následující technologie, pokud nemáš konkrétní technický důvod pro jinou volbu.

| Oblast | Technologie |
|---|---|
| Programovací jazyk | Python 3.12 nebo jiná vhodná stabilní verze kompatibilní s vybranými knihovnami |
| Desktopové UI | PySide6 |
| Extrakce textu z PDF | PyMuPDF |
| OCR skenovaných dokumentů | Tesseract OCR jako volitelná komponenta |
| Lokální LLM | Ollama přes lokální API |
| Cloudové LLM | Adaptér pro OpenAI API a rozšiřitelná podpora dalších poskytovatelů |
| Řízení agenta | Vlastní Python orchestrátor; LangGraph pouze tehdy, pokud přinese skutečný užitek |
| Validace dat | Pydantic |
| Grafy a vizualizace dat | Matplotlib |
| Diagramy | Mermaid nebo generování SVG |
| Lokální databáze | SQLite |
| Konfigurace | TOML nebo JSON |
| Testování | pytest |
| Logování | Python logging |

Neimplementuj všechny technologie jen proto, že jsou uvedené v tabulce. Vol takové řešení, které je jednoduché, udržovatelné a funkční na běžném studentském počítači.

Aplikace nesmí vyžadovat Docker, cloudový server ani placenou infrastrukturu pro základní lokální režim.

## 3. Architektura aplikace

Rozděl aplikaci do jasně oddělených modulů.

### A. Uživatelské rozhraní

Zodpovídá za:

- Import PDF souborů.
- Výběr přednášek a studijních projektů.
- Zobrazení průběhu zpracování.
- Výběr typu požadovaného výstupu.
- Zobrazení studijních materiálů a vizualizací.
- Přepínání mezi jednotlivými výstupy.
- Export dokumentů.
- Nastavení modelu a dalších parametrů.

### B. PDF Processing Engine

Zodpovídá za:

- Načítání PDF.
- Extrakci textu po jednotlivých stránkách.
- Zachování čísla stránky a pořadí obsahu.
- Rozpoznávání nadpisů, odrážek, tabulek a matematických výrazů v rozsahu možností zvolených knihoven.
- Detekci stránek bez extrahovatelného textu.
- Volitelné OCR.
- Uložení mezivýsledků pro opakované použití bez zbytečného zpracovávání stejného souboru.

### C. Lecture Understanding Engine

Analyzuje obsah dokumentů a vytváří strukturovanou reprezentaci přednášky.

Rozpoznává:

- Hlavní témata.
- Podtémata.
- Definice.
- Klíčové pojmy.
- Teorie a modely.
- Vzorce a proměnné.
- Příklady a případové studie.
- Postupy a algoritmy.
- Tabulky a číselné údaje.
- Příčinné vztahy.
- Srovnání.
- Výjimky, předpoklady a omezení.
- Vztahy mezi různými stránkami nebo dokumenty.

Každá extrahovaná informace musí mít podle možností dostupný odkaz na původní stránku nebo rozsah stránek.

### D. Agent Orchestrator

Řídí jednotlivé kroky zpracování.

Příklad workflow:

1. Načti PDF.
2. Zkontroluj kvalitu extrahovaného textu.
3. Rozděl dokument na vhodné části.
4. Analyzuj jednotlivé části.
5. Sjednoť témata a odstraň duplicity.
6. Vytvoř osnovu přednášky.
7. Vygeneruj požadované studijní výstupy.
8. Identifikuj tematické příklady vhodné pro vizualizaci.
9. Vytvoř diagramy, grafy nebo jiné reprezentace.
10. Zkontroluj návaznost výstupů na původní materiály.
11. Ulož výsledky a zobraz je uživateli.

Agent má být schopen provádět jednotlivé kroky samostatně, ale zároveň umožnit uživateli spustit pouze vybrané části workflow.

### E. LLM Provider Layer

Vytvoř jednotné rozhraní mezi agentem a jazykovými modely.

Agent nesmí být pevně závislý na jednom konkrétním LLM.

Implementuj minimálně:

- Lokální režim přes Ollama.
- Cloudový režim přes API kompatibilní s OpenAI.
- Abstraktní rozhraní umožňující přidat další poskytovatele.
- Nastavení modelu a parametrů generování.
- Kontrolu dostupnosti modelu.
- Srozumitelné chybové hlášky.
- Ošetření časových limitů, neplatných odpovědí a limitů API.
- Možnost přerušit běžící úlohu.
- Možnost opakovat neúspěšný krok bez opětovného zpracování celého dokumentu.

Pokud vybraný lokální model nepodporuje potřebné schopnosti, například strukturované výstupy, přizpůsob jeho použití nebo nabídni kompatibilní alternativu. Nepředpokládej, že každý model podporuje stejné funkce.

## 4. Propojení s LLM a režimy provozu

Aplikace musí oddělovat místo běhu agenta od místa běhu jazykového modelu.

### Režim 1: Plně lokální

- Agent běží na počítači uživatele.
- LLM běží lokálně přes Ollama.
- PDF se zpracovává lokálně.
- Výstupy se ukládají na lokální disk.
- Databáze je lokální SQLite.
- Nepoužívá se cloudové API ani online vyhledávání.
- Po instalaci všech potřebných komponent může aplikace fungovat bez internetu.

V tomto režimu musí aplikace jasně upozornit, pokud lokální model není nainstalován nebo spuštěn.

### Režim 2: Cloudové LLM přes API

Uživatel může nakonfigurovat cloudový model.

Požadavky:

- API klíče se načítají bezpečně z proměnných prostředí nebo vhodného lokálního úložiště tajných údajů.
- Klíče se nikdy nezapisují do zdrojového kódu ani běžných logů.
- Uživatel musí být informován, že obsah PDF nebo jeho části mohou být odesílány externímu poskytovateli.
- Umožni zvolit, zda se zpracují celé dokumenty, jednotlivé stránky nebo pouze vybrané části.
- Dodržuj limity poskytovatele.
- Podporuj rozdělování dlouhých dokumentů do menších částí.
- Zpracovávej odpovědi v definovaném formátu.
- Počítej s náklady na API a informuj uživatele o možnosti jejich omezení.

Neodesílej automaticky celé PDF, pokud pro daný úkol postačí relevantní extrahované části.

### Režim 3: Hybridní

Umožni lokální zpracování PDF a lokální ukládání dat při využití cloudového LLM pouze pro vybrané operace.

Příklad:

- Extrakce PDF proběhne lokálně.
- Výběr relevantních částí proběhne lokálně.
- Vybrané části se odešlou cloudovému modelu.
- Výsledek se uloží lokálně.
- Uživatel má možnost hybridní režim vypnout.

### Nastavení modelu

V uživatelském rozhraní vytvoř sekci „AI Model“, kde bude možné:

- Zvolit lokální nebo cloudový režim.
- Vybrat poskytovatele.
- Nastavit identifikátor modelu.
- Ověřit dostupnost modelu.
- Nastavit maximální délku výstupu, teplotu a další podporované parametry.
- Nastavit maximální velikost požadavku.
- Nastavit preferenci rychlosti, kvality nebo nízkých nákladů.
- Zobrazit upozornění na případné odesílání dat mimo zařízení.

Nepředpokládej konkrétní názvy modelů jako trvale platné. Používej konfigurovatelné identifikátory a ověřuj jejich dostupnost.

## 5. Zpracování PDF souborů

PDF je jediný povinný vstupní formát první verze.

Uživatel musí mít možnost:

- Vybrat jeden PDF soubor.
- Vybrat více PDF souborů.
- Přidat soubory přetažením do okna aplikace.
- Přiřadit soubory k jednomu studijnímu projektu.
- Odstranit soubor z projektu.
- Zobrazit název, počet stran a stav zpracování.
- Opakovat zpracování dokumentu.
- Vybrat konkrétní rozsah stránek.

### Extrakce

Zpracovávej obsah po jednotlivých stránkách a zachovávej:

- Název dokumentu.
- Číslo stránky.
- Extrahovaný text.
- Nadpisy a další rozpoznanou strukturu.
- Identifikaci tabulek, pokud ji použitá metoda umožňuje.
- Informaci o chybějícím nebo nekvalitním textu.

Pokud dokument obsahuje skenované stránky, nabídni OCR. Pokud extrakce selže, nevytvářej obsah, jako by byl správně přečten.

### Velké dokumenty

U dlouhých PDF:

- Používej dávkové zpracování.
- Dodržuj kontextové limity vybraného LLM.
- Zachovávej kontext napříč jednotlivými částmi.
- Sjednocuj opakující se témata.
- Zabraň ztrátě definic a důležitých výjimek.
- Umožni pokračovat po chybě.
- Neukládej zbytečně duplicitní mezivýsledky.

Použij identifikaci souboru a verze jeho obsahu pro kontrolu, zda je nutné dokument zpracovávat znovu.

### Věrnost zdroji

Při generování výstupů:

- Nevymýšlej definice, výsledky, citace ani čísla stránek.
- Rozlišuj obsah výslovně uvedený v PDF od doplňujícího vysvětlení modelu.
- Pokud něco v dokumentu chybí, uveď to.
- Pokud je text nečitelný nebo nejednoznačný, upozorni na to.
- U každého významného tvrzení umožni dohledat původní stránku.

## 6. Generování studijních materiálů

Uživatel si musí vybrat, které výstupy chce vytvořit.

### A. Strukturované shrnutí

Vytvoř shrnutí podle skutečné struktury přednášky.

Každá kapitola obsahuje podle dostupnosti:

1. Název tématu.
2. Stručný přehled.
3. Klíčové definice.
4. Vysvětlení důležitých konceptů.
5. Vzorce a jejich proměnné.
6. Příklady z přednášky.
7. Souvislosti mezi pojmy.
8. Časté chyby a nejasnosti.
9. Odkazy na zdrojové stránky.

Shrnutí nesmí být pouze seznamem odrážek. Musí být dostatečně vysvětlující, aby podle něj student mohl látce porozumět.

Umožni výběr úrovně detailu:

- Stručné shrnutí.
- Standardní studijní poznámky.
- Detailní studijní materiál.

### B. Klíčové pojmy a definice

Vytvoř seznam odborných pojmů.

U každého pojmu uveď:

- Název.
- Definici podle zdroje.
- Jednodušší vysvětlení.
- Případný příklad.
- Související pojmy.
- Stránku v PDF.

### C. Flashcards

Generuj kartičky ve formátu otázka–odpověď.

Podporuj:

- Definice.
- Vzorce.
- Rozdíly mezi podobnými pojmy.
- Příčinné vztahy.
- Aplikační otázky.
- Otázky založené na příkladech.

Kartičky musí být srozumitelné i samostatně. Vyhýbej se otázkám, které vyžadují neznámý kontext.

Umožni export do CSV a formátu vhodného pro import do Anki, například TSV nebo jiného ověřeného formátu.

### D. Procvičovací testy

Vytvářej:

- Výběr z možností.
- Pravda/nepravda.
- Krátké otevřené otázky.
- Otázky na vysvětlení principu.
- Aplikační úlohy.
- Otázky založené na konkrétních příkladech z přednášky.

Ke každé otázce uchovávej správnou odpověď, vysvětlení a zdrojovou stránku.

Nesnižuj obtížnost tím, že budou správné odpovědi vždy zjevné.

### E. Slovník a tematická mapa

Vytvoř:

- Slovník důležitých pojmů.
- Přehled hlavních a vedlejších témat.
- Vztahy mezi kapitolami.
- Grafickou tematickou mapu.
- Přehled témat, která se opakují v několika PDF.

## 7. Klíčová funkce: vizuální reprezentace tematických příkladů z PDF

Tato funkce je jednou z hlavních odlišujících vlastností aplikace.

Agent nesmí pouze generovat obecné ilustrace související s tématem. Musí identifikovat **konkrétní tematické příklady, modely, procesy, situace a případové studie skutečně zmíněné v přednáškových PDF** a podle jejich obsahu vytvářet vizuální reprezentace, které usnadní pochopení látky.

### 7.1 Identifikace vhodných příkladů

Při analýze PDF vyhledávej například:

- Praktické příklady vysvětlující teorii.
- Případové studie.
- Konkrétní číselné příklady.
- Procesy s několika kroky.
- Příčinné vztahy.
- Porovnání dvou nebo více modelů.
- Ekonomické, fyzikální nebo matematické situace.
- Příklady použití algoritmů.
- Vývoj nějakého jevu v čase.
- Situace popisované textem, které se dají převést do schématu.
- Vzorce doplněné konkrétními hodnotami.
- Příklady z tabulek, grafů nebo obrázků, pokud jsou správně dostupné.

Ne každý příklad musí být vizualizován. Vyber ty, u kterých vizuální zpracování skutečně zlepšuje pochopení.

### 7.2 Katalog nalezených příkladů

Pro každý identifikovaný příklad vytvoř strukturovaný záznam:

- Název příkladu.
- Téma a podtéma.
- Popis příkladu podle zdroje.
- Hlavní koncept, který příklad vysvětluje.
- Klíčové objekty, proměnné nebo aktéři.
- Vztahy mezi jednotlivými prvky.
- Dostupná číselná data.
- Stránka nebo stránky PDF.
- Doporučený typ vizualizace.
- Zdůvodnění, proč je daná vizualizace vhodná.
- Stav generování a validace.

Umožni studentovi zobrazit všechny nalezené příklady, vybrat ty, které chce vizualizovat, a nechat si doporučit vhodné zpracování.

### 7.3 Výběr typu vizualizace

Agent musí volit typ vizualizace podle obsahu, nikoliv používat jednu univerzální šablonu.

Používej například:

**Procesy a posloupnosti**
- Vývojový diagram.
- Schéma jednotlivých kroků.
- Časová osa.
- Diagram stavů.

**Příčinné vztahy**
- Kauzální diagram.
- Diagram příčin a následků.
- Schéma vzájemného působení proměnných.

**Hierarchie a klasifikace**
- Stromový diagram.
- Myšlenková mapa.
- Hierarchické schéma.

**Porovnání**
- Srovnávací diagram.
- Matice vlastností.
- Vennův diagram, pokud dává smysl.

**Číselné příklady a data**
- Sloupcový graf.
- Spojnicový graf.
- Bodový graf.
- Histogram.
- Tabulka výsledků.
- Graf matematické funkce.

**Abstraktní koncepty**
- Konceptuální diagram.
- Schéma vztahů.
- Vysvětlující ilustrace.
- Sada jednoduchých ikon a popisků.

**Prostorové a fyzikální situace**
- Schéma objektů, sil, pohybů nebo vzájemných vztahů.
- Geometrická reprezentace.
- Jednoduchý model situace.

### 7.4 Jak vizualizace technicky vytvářet

Preferuj lokálně generované, reprodukovatelné a editovatelné výstupy.

Používej zejména:

- SVG pro diagramy.
- Mermaid pro vývojové diagramy a některé vztahové mapy.
- Matplotlib pro grafy a matematické vizualizace.
- HTML nebo SVG pro interaktivní či strukturované reprezentace, pokud to zjednoduší aplikaci.
- PNG jako exportní formát.

Pro první verzi není nutné integrovat generování obrázků pomocí externího obrazového AI API. Upřednostni programově generované diagramy, grafy a schémata, která lze ověřit proti zdrojovým datům.

Pokud později přidáš generování ilustrací pomocí obrazového modelu, musí jít o volitelnou funkci. Nesmí nahradit přesné grafy, vzorce nebo diagramy, jejichž správnost je důležitá.

### 7.5 Pravidla přesnosti vizualizací

- Nepřidávej fakta, která ve zdroji nejsou, bez výslovného označení jako doplňující vysvětlení.
- Nevymýšlej číselné hodnoty.
- U grafů používej skutečné hodnoty ze zdroje nebo jasně označené modelové hodnoty.
- Pokud zdroj obsahuje pouze kvalitativní vztah, nevytvářej falešně přesný číselný graf.
- Zachovej směr vztahů, pořadí kroků a význam proměnných.
- U matematických grafů zkontroluj vzorec, rozsah os a jednotky.
- Pokud je vztah nejednoznačný, vyžádej si upřesnění nebo zobraz upozornění.
- Každá vizualizace musí mít název, krátké vysvětlení a zdrojovou stránku.

### 7.6 Výstup každé vizualizace

Každá vizualizace musí obsahovat:

1. Název.
2. Grafické zobrazení.
3. Vysvětlení, co má student pochopit.
4. Propojení s příslušným pojmem nebo tématem.
5. Zdrojovou stránku PDF.
6. Volbu exportu.
7. Možnost vytvořit novou verzi.

V uživatelském rozhraní vytvoř galerii vizualizací s filtrováním podle tématu, typu a zdrojového dokumentu.

## 8. Systém práce s kontextem a pamětí

Agent musí rozlišovat mezi třemi druhy informací:

1. Obsah původního PDF.
2. Odvozené závěry a shrnutí.
3. Doplňující znalosti modelu.

Tyto informace nesmějí být zaměňovány.

Používej strukturované mezivýsledky, například Pydantic modely pro:

- Dokument.
- Stránku.
- Téma.
- Pojem.
- Příklad.
- Vizualizaci.
- Otázku.
- Studijní výstup.

Pro každou položku uchovávej identifikaci zdroje.

Pokud je třeba zpracovat více dokumentů, vytvoř přehled společných témat a případných rozporů. Nepředpokládej, že dva dokumenty používají stejné definice nebo terminologii.

Doplňující informace od modelu označuj jako externí vysvětlení, nikoliv jako obsah původní přednášky.

Pokud je potřeba vyhledávání v rozsáhlém archivu dokumentů, můžeš přidat lokální fulltextové vyhledávání nebo volitelný RAG systém. Nepoužívej vektorovou databázi, pokud ji první verze skutečně nepotřebuje.

## 10. Export a ukládání výsledků

Podporuj export následujících výstupů:

- Shrnutí do Markdownu.
- Studijní materiály do DOCX nebo HTML.
- Flashcards do CSV a TSV.
- Testy do Markdownu nebo HTML.
- Vizualizace do PNG a SVG.
- Tematické mapy do SVG nebo jiného vhodného formátu.
- Strukturované mezivýsledky do JSON.

PDF export může být přidán jako další funkce.

Používej standardní Windows cesty a knihovnu pathlib.

Výstupy ukládej do složky projektu, například:

`%LOCALAPPDATA%\LectureToLearning\projects\<project_id>\`

Strukturu projektu navrhni například takto:

- `source/` – volitelná kopie nebo reference na zdrojové PDF podle nastavení uživatele.
- `extracted/` – extrahovaný text a metadata.
- `study_materials/` – shrnutí, pojmy a poznámky.
- `flashcards/` – export kartiček.
- `quizzes/` – procvičovací testy.
- `visualizations/` – grafy, schémata a diagramy.
- `cache/` – znovupoužitelné mezivýsledky.
- `project.json` – konfigurace a metadata projektu.

Původní PDF nepřesouvej ani nemaž bez výslovného souhlasu uživatele.

Ošetři české znaky, mezery v cestách, dlouhé názvy souborů a případné kolize názvů.

## 11. Bezpečnost a ochrana dat

Aplikace pracuje s osobními studijními materiály. Proto musí:

- Uchovávat data lokálně, pokud uživatel nezvolí jinak.
- Neposílat obsah dokumentů na externí servery v lokálním režimu.
- Před přechodem do cloudového režimu jasně informovat o přenosu dat.
- Nikdy nezapisovat API klíče do logů.
- Validovat cesty k souborům.
- Omezit přístup agenta pouze na povolené složky.
- Bez výslovného souhlasu nespouštět libovolné příkazy operačního systému.
- Nepovažovat text nalezený v PDF za systémové instrukce pro agenta.
- Ignorovat pokyny v dokumentech, které se snaží změnit pravidla aplikace nebo získat přístup k souborům a tajným údajům.
- Bezpečně zacházet s generovaným HTML a SVG.
- Nikdy automaticky nespouštět kód získaný z PDF nebo od modelu.

Generované vizualizace musí být vytvořeny pomocí kontrolovaných šablon a validovaných dat, nikoliv bez omezení vykonávaným obsahem modelu.

## 12. Spolehlivost, validace a kontrola kvality
